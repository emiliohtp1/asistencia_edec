1. ESTRUCTURA DEL PROYECTO
================================================================================

El proyecto sigue una arquitectura en capas (Layered Architecture):

backend/
├── app/                    # Módulo principal de la aplicación
│   ├── __init__.py        # Inicialización del módulo
│   ├── main.py            # Punto de entrada de la aplicación FastAPI
│   ├── config.py          # Configuración mediante variables de entorno
│   ├── database.py        # Gestión de conexión a MongoDB
│   ├── models/            # Modelos de datos (Pydantic)
│   │   ├── usuario.py     # Modelos relacionados con usuarios
│   │   └── asistencia.py  # Modelos relacionados con asistencias
│   ├── routes/            # Definición de endpoints HTTP
│   │   └── endpoints.py   # Todos los endpoints de la API
│   └── services/          # Lógica de negocio
│       ├── usuario_service.py    # Operaciones con usuarios
│       └── asistencia_service.py # Operaciones con asistencias
├── scripts/               # Scripts de utilidad
│   └── init_database.py   # Script para inicializar BD con datos de ejemplo
├── requirements.txt       # Dependencias del proyecto
├── start.bat             # Script de inicio para Windows
└── start.sh              # Script de inicio para Linux/Mac

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DESCRIPCIÓN:
Punto de entrada principal de la aplicación FastAPI. Configura la aplicación,
middleware CORS, eventos de inicio/cierre y el router principal.

FUNCIONALIDAD:
- Crea la instancia de FastAPI con metadatos (título, descripción, versión)
- Configura CORS para permitir peticiones desde el frontend
- Registra el router con todos los endpoints
- Maneja eventos de startup (conexión a BD) y shutdown (desconexión)
- Define endpoint raíz "/" con información básica de la API

DETALLES TÉCNICOS:
- Framework: FastAPI
- Middleware: CORSMiddleware para permitir peticiones cross-origin
- Orígenes permitidos:
  * https://asistencia-edecfront.onrender.com (producción)
  * http://localhost:5500 (desarrollo local)
  * http://127.0.0.1:5500 (desarrollo local alternativo)
- Eventos: @app.on_event("startup") y @app.on_event("shutdown")
- Servidor: Uvicorn (ASGI server)

PUNTOS IMPORTANTES:
✓ CORS configurado para desarrollo y producción
✓ Conexión a BD se establece al iniciar la aplicación
✓ Cierre limpio de conexiones al detener la aplicación
✓ Crea directorio de reportes Excel si no existe

📄 app/config.py
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DESCRIPCIÓN:
Módulo de configuración que carga variables de entorno desde archivo .env
y las expone mediante una clase Config.

FUNCIONALIDAD:
- Carga variables de entorno usando python-dotenv
- Define valores por defecto para desarrollo local
- Centraliza toda la configuración de la aplicación

VARIABLES DE CONFIGURACIÓN:
- MONGODB_URI: URI de conexión a MongoDB
  * Default: "mongodb://localhost:27017/"
  * Producción: Se obtiene de Render.com o variable de entorno
  
- DATABASE_NAME: Nombre de la base de datos
  * Default: "asistencia_edec"
  
- HOST: Dirección IP del servidor
  * Default: "0.0.0.0" (acepta conexiones de cualquier IP)
  
- PORT: Puerto del servidor
  * Default: 8000
  * Render.com proporciona PORT automáticamente
  
- EXCEL_DIR: Directorio para almacenar reportes Excel
  * Default: "./excel_reports"

DETALLES TÉCNICOS:
- Librería: python-dotenv (load_dotenv())
- Patrón: Singleton (clase Config con atributos de clase)
- Fallbacks: Todos los valores tienen defaults para desarrollo local

PUNTOS IMPORTANTES:
✓ Configuración flexible para desarrollo y producción
✓ Valores por defecto permiten ejecución sin .env
✓ Compatible con Render.com y otros servicios cloud

DESCRIPCIÓN:
Módulo que gestiona la conexión a MongoDB usando PyMongo. Implementa un
patrón singleton para reutilizar la misma conexión en toda la aplicación.

FUNCIONALIDAD:
- Establece conexión a MongoDB al iniciar
- Cierra conexión al terminar la aplicación
- Proporciona acceso a la base de datos principal y secundaria

CLASES Y FUNCIONES:
- Database: Clase singleton que almacena el cliente y la BD
- connect_db(): Establece conexión usando MONGODB_URI de Config
- close_db(): Cierra la conexión de forma segura
- get_db(): Retorna instancia de la BD principal (asistencia_edec)
- get_db_usuarios(): Retorna instancia de la BD de usuarios (usuarios_edec)

DETALLES TÉCNICOS:
- Librería: PyMongo (MongoClient)
- Patrón: Singleton para evitar múltiples conexiones
- Bases de datos:
  * asistencia_edec: BD principal (asistencias, alumnos, maestros)
  * usuarios_edec: BD de usuarios del sistema (usuarios_apodaca)

PUNTOS IMPORTANTES:
✓ Una sola conexión reutilizada (eficiente)
✓ Manejo de dos bases de datos diferentes
✓ Mensajes de confirmación al conectar/desconectar
✓ Conexión lazy (se conecta cuando se necesita)

5. UsuarioCreate (BaseModel)

7. UsuarioResponseApodaca (BaseModel)

4. ARCHIVOS DE SERVICIOS (Lógica de Negocio)
================================================================================

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📄 app/services/usuario_service.py
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DESCRIPCIÓN:
Contiene toda la lógica de negocio para operaciones con usuarios. Interactúa
directamente con MongoDB y maneja la transformación de datos entre modelos
Pydantic y documentos MongoDB.

FUNCIONES PRINCIPALES:

1. obtener_usuario_por_matricula(matricula: str)
   - Busca en colecciones 'alumnos' y 'maestros'
   - Retorna UsuarioResponse con encontrado: bool
   - BD: asistencia_edec

2. obtener_todos_alumnos() / obtener_todos_maestros()
   - Lista todos los alumnos/maestros
   - Ordena por matrícula
   - Convierte ObjectId a string

3. obtener_datos_alumno_bachillerato(matricula: str)
   - Busca en 'alumnos_bachillerato_apodaca'
   - Mapea campos MongoDB (mayúscula) a modelo (minúscula)
   - Maneja matrícula como string e int
   - Retorna usuario_datos

4. obtener_datos_alumno_universidad(matricula: str)
   - Similar a bachillerato pero en 'alumnos_universidad_apodaca'

5. crear_usuario_apodaca(usuario: UsuarioCreate)
   - Crea usuario en 'usuarios_apodaca' (BD: usuarios_edec)
   - Hashea contraseña con bcrypt
   - Valida correo único
   - Establece autorizado: False por defecto
   - Retorna usuario sin contraseña

6. autenticar_usuario_apodaca(correo: str, contraseña: str)
   - Verifica credenciales
   - Compara contraseña hasheada con bcrypt
   - Retorna UsuarioResponseApodaca o None

7. cambiar_contraseña_usuario_apodaca(datos: UsuarioCambiarContraseña)
   - Valida contraseña actual
   - Hashea nueva contraseña
   - Actualiza en BD

8. cambiar_autorizado_usuario_apodaca(datos: UsuarioCambiarAutorizado)
   - Actualiza campo 'autorizado' de usuario
   - Retorna usuario actualizado

9. obtener_todos_usuarios_apodaca()
   - Lista todos los usuarios
   - Elimina contraseñas de respuesta
   - Asegura campo 'autorizado' existe (default: False)

10. obtener_usuario_por_correo_apodaca(correo: str)
    - Busca usuario por correo
    - Retorna usuario sin contraseña

11. eliminar_usuario_por_correo_apodaca(correo: str)
    - Elimina usuario por correo
    - Retorna información del usuario eliminado

12. crear_alumno_bachillerato(alumno: usuario_datos)
    - Crea alumno en 'alumnos_bachillerato_apodaca'
    - Valida matrícula única
    - Mapea campos a mayúscula (formato MongoDB)

13. crear_alumno_universidad(alumno: usuario_datos)
    - Similar a bachillerato pero en 'alumnos_universidad_apodaca'

14. eliminar_alumno_bachillerato(matricula: str)
    - Elimina alumno de bachillerato
    - Maneja matrícula como string e int

15. eliminar_alumno_universidad(matricula: str)
    - Elimina alumno de universidad

DETALLES TÉCNICOS:
- Librerías: bcrypt (hash de contraseñas), pymongo (MongoDB)
- Hashing: bcrypt con salt automático
- Mapeo: Campos MongoDB en mayúscula → Modelos en minúscula
- Validaciones: Correo único, matrícula única
- Seguridad: Contraseñas nunca se retornan en respuestas

PUNTOS IMPORTANTES:
✓ Separación de lógica de negocio de rutas HTTP
✓ Manejo robusto de tipos (string/int para matrículas)
✓ Seguridad: contraseñas hasheadas con bcrypt
✓ Campo 'autorizado' con valor por defecto para usuarios antiguos
✓ Dos bases de datos: asistencia_edec y usuarios_edec

📄 app/services/asistencia_service.py
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DESCRIPCIÓN:
Contiene la lógica de negocio para operaciones con asistencias y fichados.
Maneja zona horaria de México y validaciones de registros únicos por día.

FUNCIONES PRINCIPALES:

1. obtener_hora_mexico()
   - Retorna datetime actual en zona horaria de México (America/Mexico_City)
   - Usa pytz para manejo de zonas horarias
   - Obtiene hora en UTC primero y luego convierte a zona horaria de México
   - Asegura fecha y hora correctas independientemente de la zona horaria del servidor
   - Formato: datetime con timezone

2. registrar_asistencia(matricula: str, nombre: str)
   - Registra asistencia en 'asistencia_general_apodaca'
   - Valida: Solo un registro por matrícula por día
   - Guarda: Matricula, Nombre, Fecha (DD/MM/YYYY), Hora (HH:MM)
   - Incluye timestamp para ordenamiento
   - Lanza ValueError si ya existe registro del día

3. obtener_todas_asistencias()
   - Lista todas las asistencias de 'asistencia_general'
   - Ordena por timestamp descendente (más recientes primero)
   - Convierte ObjectId y timestamp a formatos serializables

4. obtener_asistencias_por_matricula(matricula: str)
   - Filtra asistencias por matrícula
   - Colección: 'asistencia_general'

5. obtener_todas_asistencias_apodaca()
   - Similar a obtener_todas_asistencias pero en 'asistencia_general_apodaca'

6. obtener_asistencias_apodaca_por_matricula(matricula: str)
   - Busca por 'Matricula' (mayúscula)
   - Intenta como string e int
   - Colección: 'asistencia_general_apodaca'

7. registrar_fichado_apodaca(fichado_data: dict)
   - Registra fichado en 'fichados_apodaca'
   - Agrega automáticamente fecha_registro_ficha
   - Guarda todos los datos del alumno

8. obtener_fichados_apodaca_agrupados()
   - Agrupa fichados por nombre y matrícula
   - Si hay duplicados, muestra uno con campo 'cantidad_fichas'
   - Lógica de agrupación en memoria

9. eliminar_fichado_mas_antiguo_por_matricula(matricula: str)
   - Elimina el registro más antiguo de un fichado por matrícula
   - Busca todos los registros con la misma matrícula
   - Ordena por fecha_registro_ficha (ascendente) para encontrar el más antiguo
   - Elimina el registro más antiguo encontrado
   - Retorna información del registro eliminado y total de registros restantes
   - Lanza ValueError si no se encuentra ningún registro con esa matrícula

DETALLES TÉCNICOS:
- Librería: pytz para zonas horarias
- Zona horaria: America/Mexico_City (UTC-6)
- Formato fecha: DD/MM/YYYY (formato mexicano)
- Formato hora: HH:MM (24 horas)
- Validación: Un registro por matrícula por día
- Timestamp: Se guarda para ordenamiento y consultas

PUNTOS IMPORTANTES:
✓ Manejo correcto de zona horaria de México (Monterrey)
✓ Conversión UTC a zona horaria local para precisión
✓ Prevención de registros duplicados por día
✓ Formato de fecha legible (DD/MM/YYYY)
✓ Agrupación inteligente de fichados duplicados
✓ Eliminación selectiva del registro más antiguo por matrícula
✓ Conversión automática de ObjectId a string para JSON

DESCRIPCIÓN:
Define todos los endpoints HTTP de la API REST. Organizados por funcionalidad

   - Services: Lógica de negocio

   - Cada módulo tiene una responsabilidad única
   - Fácil mantenimiento y testing

   - Nunca se retornan en respuestas
   - Validación antes de cambiar

   - Campo 'autorizado' controla acceso
   - Nuevos usuarios: autorizado = false

   - America/Mexico_City (UTC-6) - Zona horaria de Monterrey, México
   - Usa pytz para conversión correcta
   - Obtiene hora en UTC primero y luego convierte a zona horaria local

   - Fecha: DD/MM/YYYY (formato mexicano)
   - Hora: HH:MM (24 horas)
   - Timestamp: datetime con timezone para ordenamiento

3. Validaciones
   - Un registro por matrícula por día
   - Previene duplicados
